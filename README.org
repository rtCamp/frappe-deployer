#+title: fmd — Frappe Manager Deployer

Zero-downtime Frappe deployments on top of [[https://github.com/rtcamp/frappe-manager][Frappe Manager]]: atomic releases, instant symlink switch, and rollback.

* How it works

Every deploy builds a new *immutable, timestamped release* directory. The live bench is a *symlink* that fmd repoints atomically, so a switch is instant and a rollback is just repointing back. Persistent state (database, site files, configs, logs) lives once in ~deployment-data/~ and is symlinked into every release — releases share data, only code/assets change.

#+begin_src
configure ──▶ create ──▶ switch
(one-time)   (build a    (repoint symlink,
             release,     migrate, restart —
             no change)   atomic)
#+end_src

* Requirements

- Python ~>=3.13,<3.14~
- Docker + Docker Compose v2
- Frappe Manager, with an existing bench for the site

* Install

#+begin_src bash
uv tool install frappe-deployer      # recommended
# or
pipx install frappe-deployer
# from source
git clone https://github.com/rtcamp/fmd.git && cd fmd && pip install -e .
#+end_src

* Quick start

#+begin_src bash
# 1. One-time: convert an FM bench to the fmd release layout
fmd release configure site.localhost

# 2. Deploy Frappe + ERPNext (configure → create → switch)
fmd deploy pull site.localhost \
  --app frappe/frappe:version-15 \
  --app frappe/erpnext:version-15 \
  --maintenance-mode --backups

# 3. Verify
fmd release list site.localhost
fmd release info site.localhost
#+end_src

App format: ~org/repo:ref~ or ~org/repo:ref:subdir/path~ (monorepo).

* Commands

#+begin_src bash
# Deploy — full automated flow (configure if needed → create → switch)
fmd deploy pull  <site>|--config site.toml [--app ...]   # build + switch on this server
fmd deploy ship  --config site.toml                      # build local/CI → rsync → switch on remote

# Release — manual lifecycle control (CI/CD)
fmd release configure <site>            # one-time workspace setup
fmd release create    <site>            # build a release; no live change (--mode exec|image, --build-dir)
fmd release switch    <site> <release>  # atomically activate a release
fmd release list      <site>            # list releases
fmd release shell     --config s.toml   # interactive shell in a release's build container
fmd release info      <site>            # per-app git repo/branch/commit/tag

# Utilities
fmd remote-worker enable <site> --rw-server 192.168.1.100   # open Redis/MariaDB ports
fmd remote-worker sync   <site> --rw-server 192.168.1.100   # sync active release to worker
fmd search-replace <site> "old.com" "new.com" --dry-run     # DB-wide string replace
fmd cleanup <site> -r 3 -b 5 -y                             # keep 3 releases, 5 backups
#+end_src

Global ~-v/--verbose~ must precede the subcommand. Every command accepts ~-c/--config~. Run ~fmd <command> --help~ for full options.

* Configuration

A ~site.toml~ drives everything; CLI flags override it, which override defaults.

#+begin_src toml
site_name = "site.localhost"
bench_name = "site"          # optional, defaults to site_name
github_token = "ghp_xxx"     # for private repos

[[apps]]
repo = "frappe/frappe"
ref  = "version-15"

[[apps]]
repo = "frappe/erpnext"
ref  = "version-15"

[release]
releases_retain_limit = 7
python_version = "3.13"
use_fc_apps = false          # import app list from Frappe Cloud
use_fc_deps = false          # import Python version from Frappe Cloud

[switch]
migrate = true
maintenance_mode = true
maintenance_mode_phases = ["migrate"]   # valid: "drain", "migrate"
backups = true
rollback = false
search_replace = true
use_fc_db = false            # restore latest Frappe Cloud DB backup at switch
restore_db_from_site = ""    # restore DB from another local FM bench/site

[fc]
api_key = "fc_xxx"
api_secret = "fc_xxx"
site_name = "mysite.frappe.cloud"
team_name = "my-team"

[remote_worker]
server_ip = "192.168.1.100"
ssh_user  = "frappe"
ssh_port  = 22
#+end_src

See [[file:example-config.toml][example-config.toml]] for the complete annotated schema (all sections, hooks, and defaults).

** Restoring a database from another site

~[switch] use_fc_db~ (Frappe Cloud) and ~[switch] restore_db_from_site~ (another local FM bench) seed the site's DB at switch time. fmd copies the *source site's* ~encryption_key~ into the target ~site_config.json~ before ~bench migrate~, so Fernet-encrypted secrets (API keys, SMTP/OAuth passwords) stay decryptable — this is Frappe's documented approach; there is no key-rotation command. When ~search_replace~ is on, the old site name is rewritten to the new one.

* Deploy modes

| Mode | Build location | Deploy target | When to use                                  |
|------+----------------+---------------+----------------------------------------------|
| pull | Target server  | Same server   | Server has build capacity; simplest setup    |
| ship | Local / CI     | Remote (SSH)  | Offload builds, cross-arch, multi-server      |

*ship* builds in Docker locally or in CI, rsyncs the finished release to the remote, then runs ~release configure~ + ~release switch~ there via ~uvx~ — the remote only needs SSH, rsync, and uv. Requires a ~[ship]~ section:

#+begin_src toml
[ship]
host      = "192.168.1.100"
ssh_user  = "frappe"
ssh_port  = 22
# remote_path = ""   # empty = auto-detect $HOME/frappe/sites/<site>
#+end_src

* GitHub Actions

Deploy on push with the composite action ~rtcamp/frappe-deployer@main~ (~command: pull~ or ~command: ship~):

#+begin_src yaml
- name: Deploy
  uses: rtcamp/frappe-deployer@main
  with:
    command: pull                       # or: ship (add docker/setup-buildx-action first)
    sitename: ${{ vars.SITE_NAME }}
    config_path: .github/configs/site.toml
    gh_token: ${{ secrets.GH_TOKEN }}
    ssh_private_key: ${{ secrets.SSH_PRIVATE_KEY }}
    ssh_server: ${{ secrets.SSH_SERVER }}
    ssh_user: ${{ secrets.SSH_USER }}
#+end_src

Full input reference: [[file:action.yml][action.yml]]. Generate a dedicated deploy key:

#+begin_src bash
ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/deploy_key -N ""
cat ~/.ssh/deploy_key        # → SSH_PRIVATE_KEY secret
cat ~/.ssh/deploy_key.pub    # → append to remote ~/.ssh/authorized_keys
#+end_src

* Directory structure

#+begin_src
~/frappe/sites/<site>/
├── workspace/
│   ├── frappe-bench → release_YYYYMMDD_HHMMSS   (symlink to active release)
│   ├── deployment-data/                          (persistent across releases)
│   │   ├── sites/   (DB, files)
│   │   ├── config/  (supervisor configs)
│   │   └── logs/
│   ├── release_YYYYMMDD_HHMMSS/                   (one immutable release)
│   │   ├── apps/  env/ (venv)  .uv/  .fnm/
│   │   ├── sites → ../deployment-data/sites
│   │   └── <site>.toml                            (config snapshot)
│   └── .cache/
└── deployment-backup/
    └── release_YYYYMMDD_HHMMSS/                   (pre-switch DB + config backups)
#+end_src
